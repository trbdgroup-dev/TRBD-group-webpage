# Staff Engineer — stage1-foundations

**Date:** 2026-10-22

## Conventions
- **TypeScript strict**, no `any` in app code. Payload types generated to `src/payload-types.ts` (`payload generate:types`), committed and checked in CI (regenerate + `git diff --exit-code`).
- **Pinned versions** (no `^`/`~`) for next, react, payload and @payloadcms/*.
- **File naming:** components `PascalCase.tsx`; everything else `kebab-case.ts`. One block = one folder with `config.ts` and `Component.tsx`.
- **Server first:** React Server Components by default; `"use client"` only for `HeroSlideshow` (and later forms).
- **Pure logic out of components:** SEO builders, access rules, slug rules, hero reducer live in `lib/` as pure functions with unit tests.
- **Styling:** Tailwind 4 utilities with tokens in `src/app/(frontend)/globals.css` `@theme`. No arbitrary hex values in components; use tokens.
- **Imports:** `@/` alias for `src/`.
- **Env access:** only via `src/lib/env.ts` (Zod-validated); fail fast at startup on missing required vars.
- **Commits:** Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `test:`), small and logical.

## Cross-cutting concerns
- **Errors:** route-level `error.tsx` and `not-found.tsx` (branded). Sentry captures server and client errors when `SENTRY_DSN` is set; `beforeSend` scrubs request bodies, cookies, emails, IPs.
- **Logging:** Payload's logger on the server; no `console.log` left in committed code (lint rule).
- **Accessibility:** every interactive element keyboard reachable; focus styles from tokens; images require alt (schema-enforced).
- **Content safety:** Lexical rich text rendered through Payload's serializer only; no `dangerouslySetInnerHTML` except JSON-LD `<script>` built from our own objects and escaped with `JSON.stringify` + `<` replacement.

## Standards for later stages (from ADR-001/002)
- New staff-managed data → Payload collection in schema `payload`.
- New public-user data → Drizzle table in schema `app` with RLS policy and tests.
- Public routes never use the Payload DB connection for `app` data.

## Reuse
- Greenfield; reuse Payload's official Next.js integration files generated by `create-payload-app` (blank template) for the `(payload)` route group, not hand-written.
